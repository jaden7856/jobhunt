# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static, self-contained HTML files generated by Python scripts (standard library only, no build step, no external CSS/JS). The one external resource is the title face (Nanum Myeongjo from Google Fonts); without network it falls back to installed Myeongjo faces (AppleMyungjo, Batang) and the page still works. The same file must open in any browser and be produced and read by any AI agent (Claude Code, Codex, Grok, …) — no agent-specific runtime or hosting features. Where a host can publish HTML (e.g. Claude Artifacts) that is an optional delivery step on top of the file, never a requirement.

## Users

One developer running their own job search with an AI agent: a Korean backend engineer who reviews the posting queue on a Mac browser (wide screen), usually weekly after a scan. Occasionally the same page is shown to someone else (a mentor or friend) who has never seen the tool, so labels must read without insider shorthand.

## Product Purpose

jobhunt finds Korean developer job postings (job boards and companies' own career sites), scores each against the user's experience and conditions, and builds a tailored resume PDF per posting. The posting report is where the user decides what to apply to next and keeps track of applications and deadlines. Success: the user can pick this week's applications and spot anything closing soon in a couple of minutes, and trusts why each posting got its score.

## Positioning

Scores are computed by a script from line-by-line judgments (work fit, required, preferred, direction, signals, caps), not guessed. Each row carries the one-line reason and the judgment file behind it, so the user can correct the rule rather than argue with a number.

## Operating Context

- Generated from `data/search/pipeline.md`, `data/applications/tracker.md`, and `data/search/judgments/*.yaml` (private, git-ignored) by `scripts/tracker.py`.
- Typical size 100–200 open rows plus a handful of application records.
- Verdict bands: 지원 권장 (4.0+), 지원 고려 (3.5–3.9), 보류 (3.0–3.4), 제외 (<3.0), 확인 필요 (no body); application states 지원함 · 서류합격 · 면접 · 불합격 · 합격.
- Columns in use: 회사, 포지션, 근무지, 점수, 판정, 지원 여부, 새로 찾음, 마감, 한 줄 근거, plus the posting URL.

## Capabilities and Constraints

- All user-facing text is Korean; code identifiers stay as they are.
- Personal data never goes into the repository; the generated report lives under `data/` and is not committed.
- Public examples in the repo use fictional companies only.
- Open decision: whether the report needs interactive filtering beyond what static HTML with inline script provides.

## Evidence on Hand

Real report data exists only in the user's private `data/`. Public docs and screenshots must use fictional rows (see `examples/`).

## Product Principles

1. Decide fast: the next action (apply, check, skip) is visible without reading every row.
2. Show the reason, not just the number: every score links to its evidence.
3. Same file everywhere: nothing depends on one AI vendor or hosting feature.
4. Plain Korean a stranger can follow.
