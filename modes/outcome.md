# Mode: outcome — learning from results

Look across application results and interview debriefs, find what repeats, and propose rule changes. Read `modes/_shared.md` first.

## When

The user asks ("결과 분석해줘", "왜 자꾸 떨어지지"), or three or more results have accumulated since the last analysis (`modes/track.md`, `modes/interview.md` debrief).

## Steps

1. Gather: `data/applications/tracker.md` (state per application), the judgment file and `.eval.md` per application, `data/interview/log.md`, `data/profile/calibration.md`.
2. Line results up against scores: high score but rejected, low score but passed. For each, ask at which stage it ended (서류 / 코딩 / 직무 / 인성 / 처우).
3. Classify the cause by stage:
   - 서류 rejections with high scores → a rule the score missed (key preferred, seniority, domain) → `references/scoring.md` (common) or `targets.yaml` (personal)
   - 서류 passes with low scores → the rules are too strict somewhere
   - interview rejections → the debrief's stalled answers (facts, concepts, structure) → stories to write, concepts to study, resume lines to cut
4. Report to the user in Korean: the pattern, the evidence (which applications), the proposed change, and what stays a single case. Apply only what the user accepts, and record it in `calibration.md`.
