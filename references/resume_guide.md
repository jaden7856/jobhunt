# 이력서 작성 일반 규칙

기존 가이드 문서(작성 가이드, 서류 탈락 원인 진단, GitLab 근거 경력 재구성, 커밋 단위 분석)에서 사람에 상관없이 쓸 수 있는 규칙만 추렸다. SKILL.md 와 부딪히면 SKILL.md 를 따른다.

## 문서 전체

- 15초 스캔 문서다. 첫 페이지에 요약·기술·대표 프로젝트 시작이 보여야 한다.
- 목표 2~3쪽. 단일 컬럼 PDF. 표·이미지로 붙여넣지 않는다(ATS 파싱, 검색, 수정 불가).
- 프로젝트는 5개 이하. 모든 프로젝트를 넣지 않는다. 공고와 먼 것은 OTHER 한 줄로 내린다.
- 경력 기간에 빈 구간이 길게 남지 않게 EXPERIENCE 타임라인으로 시간 축을 잇는다(연도별 3~4줄).
- 지원동기는 넣지 않는다. 회사가 따로 요구할 때만 5~7줄로 별도 작성.
- 기술 스택은 공고와의 교집합 8~12개. 숙련도 게이지·별점 금지. 안 써본 기술 금지.
- 플레이스홀더(【 】, N건, TODO)를 남긴 채 내지 않는다. 이것만으로 탈락 사유가 된다.
- 파일명 `이름_직무_버전.pdf`. 모바일에서 한 번 열어본다.

## 프로젝트 블록

```
[번호] 임팩트가 보이는 제목 (가능하면 숫자: "API 호출 99% 감소 : …")
기간 · 역할(단독/주도/원인 분석·구현) · 기술 칩
요약 바 1~2줄 (문제, 해결, 결과)
문제       상황 + 왜 중요한지(비즈니스 영향) 2~3줄
원인 규명  어떻게 찾았나 (로그, 재현 테스트, 코드 추적, 프로파일링) 1~2줄
선택지     2~3개. 기각안은 장점을 먼저 인정하고 단점으로 기각. 채택안은 근거와 약점 통제 방법까지
실행       불릿 3~4개. 행동 동사 + 구체 기법
결과       KPI 2~3개 (큰 숫자 + 설명)
↳ 관련 글  1~2개
```

- 면접관은 실행보다 "왜 그 선택을 했나"를 본다. 선택지 행이 가장 중요하다.
- 한 프로젝트를 5~7줄 문단으로 쓰지 않는다. 문단은 3줄 이내.

## 수치

- 수치는 전후 비교로 쓴다 (2,000회 → 20회, 1–2일 → 4–5시간).
- 수치에는 원인을 붙인다 (무엇을 바꿔서 그렇게 됐나).
- 규모·변화율·빈도·절감 네 방향에서 찾는다.
- 자료에 없는 수치는 만들지 않는다. 확정 안 된 수치는 쓰지 않는다.
- 스스로 정의한 테스트 결과("재현 테스트 0건")보다 운영 지표(문의, 장애, 재처리 건수)가 강하다. 있으면 그쪽을 쓴다.

## 회사 언어로 옮기기

같은 경험도 지원처에 맞춰 다시 쓴다.
- 인프라·플랫폼 조직: 규모(VM N대 이관), 연동 대상 API, Operator/CRD 같은 도메인 용어
- 서비스 회사: 분산 작업 상태 정합성, 동시성, 외부 API 최적화, 이벤트 파이프라인
- 공고에 "이력서 작성 추천사항"이 있으면 그 순서대로 경험을 배치한다.
- 맞춤본은 기본본을 복사해 공고 용어로 통일하고, 관련 경험을 위로 올리고, 무관한 줄을 지운다.

## 링크

- 링크는 프로젝트당 1~2개. 남발하면 읽기 힘들고 "급조한 블로그" 인상을 준다.
- 제출 전 모든 링크를 실제로 열어본다. 비활성 GitHub·블로그는 오히려 감점.

## 근거 자료에서 경험 찾기 (git·GitLab)

- 작성자 기준 커밋 로그와 MR을 기간별로 묶어 프로젝트 후보를 만든다.
- revert, "다시 하향", 닫힌 MR 같은 흔적이 시행착오 서사가 된다 (첫 시도 폐기 → 재접근).
- 커밋 본문에 문제·설계·트레이드오프가 적혀 있으면 그대로 근거로 쓴다.
- MR 건수·저장소 수·고객사명은 이력서에 쓰지 않는다(사용자가 달리 정하지 않는 한).
- 커밋·디프에서 추론한 해석(왜 그랬는지)은 반드시 "확인 필요"로 표시하고 사용자 확인을 받는다.

## 제출 전 체크리스트

- [ ] 첫 페이지에 요약·기술·대표 프로젝트
- [ ] 프로젝트 5개 이하, 불릿 3~4개, 한 불릿 한 줄 반 이내
- [ ] 결과마다 전후 수치 + 원인
- [ ] 지원동기 없음, 플레이스홀더 없음, "확인 필요" 없음
- [ ] 기술 스택 공고 교집합, 숙련도 표시 없음
- [ ] 링크 1~2개씩, 전부 열림
- [ ] 목표 페이지 수, 제목이 페이지 끝에 홀로 남지 않음
- [ ] 채용 경험자 1명에게 15초 스캔 테스트 ("뭐가 기억에 남나")
